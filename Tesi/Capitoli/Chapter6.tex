\chapter{Numerical Experiments}\label{capitolo:6}
In this chapter, the numerical experiments to assess and validate the \texttt{expm\_mp} algorithm will be thouroughly described. Then, their outcomes will be presented, emphasizing the most relevant ones. A critical discussion of the obtained results will be given, and conclusions will be drawn.

\section{Experimental setup}
Since the algorithm under consideration operates in arbitrary precision, the main concern is accuracy.
In fact, multiprecision algorithms are frequently used to compute reference solutions against which lower precision methods are compared. Reliability is of paramount importance, more so than computational performance.

The testing strategies must therefore be designed carefully. More generally, the assessment of numerical algorithms is already a delicate task in itself; one that demands care and awareness, as each assumption and each approximation can have a huge impact on the overall process, an impact that can easily be overlooked.
As the working precision increases, these effects may become even more pronounced, in particular when a correspondingly higher level of accuracy is demanded. 

%The problem of designing the experimental setup can be a subtle one in general, the multiprecision setting in which the algorithm operates makes it even subtler than what it seems at first.
%Indeed, the finite-precision representation of the input and the output play an important role, more so as the precision is increased.

Well estabilished and widely accepted testing practices do exist; however there is no universally accepted and codified testing procedure, as each case has its own set of nuances.
\smallskip

In~\cite{higham:hf19_mpexpm} the proposed algorithm is tested on matrices taken from many sources, most of them having elements that are explicitely specified, such as
\begin{equation}\label{eqn:Higham_test_matrix}
	A = \begin{pmatrix}
		\mathtt{0} & \mathtt{1e{-4}}\\
		\mathtt{-1e{-4}} & \mathtt{0}
	\end{pmatrix}.
\end{equation}
The reference solution is computed using \texttt{exp\_mct} -- the \texttt{expm} function provided by the Multiprecision Computing Toolbox -- with $2d$ the significant digits, where $d$ is the number of digits of precision that the algorithm under test is running with. This first testing strategy can be described as in code snippet~\ref{alg:first_test_strat} 
\begin{algorithm}[H]
	\caption{\emph{First testing strategy}}
	\label{alg:first_test_strat}
	\begin{algorithmic}[1]
		\State $A = \mathtt{get\_from\_gallery}(\ )$ \Comment{$A$ is in double precision}
		%\Lcomment{}
		\State $Y_{\textup{true}} = \mathtt{ref\_sol}(A)$	\Comment{Computes the reference solution}
		\State $\hat{Y} = \mathtt{exp\_mp}(A)$
		\State \Return $\norm*{Y_{\textup{true}}-\hat{Y}}/\norm{Y_{\textup{true}}}$
	\end{algorithmic}
	%	\begin{algorithmic}
		%		\Function{ref\_sol}{$A$}
		%			\State 
		%		\EndFunction
		%	\end{algorithmic}
\end{algorithm}

\noindent For the accuracy analysis of the algorithm proposed in~\cite{exptayotf18}, the authors use matrices of the form $H^{\top}DH$, where $H$ is a Hadamard matrix normalized in order to be orthogonal (i.e. each entry is divided by $\sqrt{n}$), and $D$ is a diagonal matrix with entries uniformly randomly distributed in $[-50,50] + \mathtt{i}[-50,50]$. This second testing strategy can be described as in code snippet~\ref{alg:second_test_strat}.
\begin{algorithm}[H]
	\caption{\emph{Second testing strategy}}
	\label{alg:second_test_strat}
	\begin{algorithmic}[1]
		\State $H = \mathtt{hadamard}(n)$
		\State $H = H / \sqrt{n}$
		\State $D = \operatorname{Diag}\qty(100\,\mathtt{rand}(n)\mathtt{.-}50 + \mathtt{i}\qty(100\,\mathtt{rand}(n)\mathtt{.-}50))$
		\State $\tilde{A} = H^{\top}\!\mathtt{*}D\mathtt{*}H$ \Comment{$A\coloneqq H^{\top}\!D H$}
		\State $Y_{\textup{true}} = H^{\top}\!\mathtt{*}\exp(D)\mathtt{*}H$
		\State $\hat{Y} = \mathtt{exp\_mp}(\tilde{A})$
		\State \Return $\norm*{Y_{\textup{true}}-\hat{Y}}/\norm{Y_{\textup{true}}}$
	\end{algorithmic}
\end{algorithm}

\noindent This second kind of test looks attractive at first, as the exact exponential can be cheaply and easily computed as $H^{\top}\!\exp(D)H$, theoretically, without the need to run multiprecision algorithms whose reliability is still being questioned. 
By contrast, one may raise two objections to the first testing strategy. Firstly, the reference is produced by an algorithm that is under scrutiny; secondly, and most importantly, the input data is in double precision and explicitely specified.

How can we then hope to observe an error less than $u_{53}$, even with an algorithm that uses higher precision internally? Since, as we've seen, promoting numerical expressions doesn't always improve the accuracy, is an error being introduced at the very start?
Is the accuracy of the computation -- whatever the precision it's being carried with -- limited by that of double precision floating point numbers? 
\smallskip

The latter strategy introduces a tiny error that the former one does not introduce. Furthermore, the three questions with which this section ends are misguiding and fallacious.  

\subsection{The perplexities in the first testing strategy}
When one sees $A$ as in~\eqref{eqn:Higham_test_matrix}, one is \emph{biased} to think that it comes from $A = \mathcal{A}+\Delta\mathcal{A}$, where $\mathcal{A}=\left(\begin{smallmatrix}
	0 & 10^{-4}\\ -10^{-4} & 0
\end{smallmatrix}\right)$ is the matrix that was supposed to be fed to the algorithm but can't be because of rounding errors. Therefore, one concludes, $A$ is not an appropriate test matrix for \texttt{exp\_mp} because the algorithm will always fail to compute $\mathcal{Y}\coloneqq\exp(\mathcal{A})$ due to intrinsic error in its input. 
%\begin{oss*}
%	\textcolor{red}{Of course the elements in $A$ reinforce this bias. But the bias is more general I would say. \`E il discorso che i dati in doppia precisione sono accompagnati dalla percezione di essere ``erronei''.}
%\end{oss*}

Let $Y\coloneqq\exp(A)$. The algorithm \texttt{exp\_mp} will produce an approximation $\hat{Y}$.
More formally, the (fallacious) argument is as follows: to correctly assess the quality of our algorithms, $\norm*{\hat{Y}-\mathcal{Y}}/\norm{\mathcal{Y}}$ should be measured. Except in some special cases, $\mathcal{Y}$ will never be gotten, however
\begin{equation}\label{eqn:Y_rel_err_expansion}
	\begin{aligned}
	\frac{\norm*{\hat{Y}-\mathcal{Y}}}{\norm{\mathcal{Y}}} &= \frac{\norm*{\hat{Y}-Y+Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}\frac{\norm*{Y-\mathcal{Y}+\mathcal{Y}}}{\norm{\mathcal{Y}}}+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}\left(1+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\right)+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\dot{=}\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}+\kappa_{\exp}(\mathcal{A})\frac{\norm{\Delta\mathcal{A}}}{\norm{\mathcal{A}}}
\end{aligned}
\end{equation}
where $\dot{=}$ denotes equality up to first order terms (i.e. higher order terms have been dropped). A term $\norm{\Delta\mathcal{A}}/\norm{\mathcal{A}}$ appears, with $\norm{\Delta\mathcal{A}}=O(u_{53})$, and is further amplified by $\kappa_{\exp}(\mathcal{A})$. Therefore the forward error can be higher than what we should be able to get, namely something close to $\kappa_{\exp}(A)u_{256}$. Even when the multiprecision algorithm may seem to compute the solution accurately, the actual underlying approximation error can be bigger than what it should be. Using $A$ we will never know for sure. 

\subsubsection*{Addressing the objections}
Behind the fallacy there is the belief that only $\norm*{\mathcal{Y}-\hat{\mathcal{Y}}}/\norm{\mathcal{Y}}$ would be able to capture errors of the order of $u_{256}$, where $\hat{\mathcal{Y}}$ is the approximation of $\mathcal{Y}$ that the algorithm would compute; but since we're doomed to use $\hat{Y}$ instead of $\hat{\mathcal{Y}}$ our error reads will be unreliable. 

The steps in~\eqref{eqn:Y_rel_err_expansion} are correct,  
the point is that although $\exp(A)$ may never be gotten exactly, $Y$ can be pushed to be arbitrarily close to it, just like with any real matrix. Thus, $\norm*{\hat{Y}-Y}/\norm{Y}$ can potentially be of the order of $u_{256}$. This forward error, and not $\norm*{\mathcal{Y}-\hat{\mathcal{Y}}}/\norm{\mathcal{Y}}$, is the appropriate measure for the quality of the approximations that our algorithm computes.
\smallskip 

Returning to the three questions that introduced the ``fallacious argument'', floating point data usually comes with this notion of being ``flawed'' or ``uncertain'', but is just a matter of roles.
The \emph{bias} is to think that the available digits in $A$ come from a truncation that $\mathtt{big.()}$ should somehow undo. For all we know, the extra digits returned by the command are correct (whatever ``correct'' means). $A$ is the input to the algorithm, it may be affected by intrinsic error or it may not, but we will never know; the fact that is in double precision doesn't imply that it is. The point is that it doesn't matter. 
In fact, $A$ is better thought of as a real square matrix like any other, although containing double precision data. As such, it's a perfectly valid input to an algorithm running in higher precision. $\mathcal{Y}$ is just a distraction.


The documentation of the Python arbitrary precision library \textsc{mpmath}~\cite{mpmath} puts it very well:
\begin{quotation}
	Contrary to popular belief, floating-point \emph{numbers} do not come with an inherent ``small uncertainty'', although floating-point \emph{arithmetic} generally is inexact. Every binary floating-point number is an exact rational number. With arbitrary-precision integers used for the mantissa and exponent, floating-point numbers can be added, subtracted and multiplied \emph{exactly}. \elide
	
	Floating-point arithmetic is generally approximate because the size of the mantissa must be limited for efficiency reasons \elide.
\end{quotation}


\subsection{Why the second testing strategy is (subtly) deceitful}
Let's now consider the second testing strategy, which is summarized in the code snippet~\ref{alg:second_test_strat}.

%Similarly to the discussion of the first strategy, identifying what is the input data, which matrix exponential we really want to compute, the crucial issue
\begin{notazione}
	Let either the dot symbol or no symbol at all, as in $A\cdot B$ and $AB$ respectively, denote the product in exact arithmetic. Let the $\mathtt{*}$ symbol denote the same operation in floating point arithmetic.
\end{notazione}

%Similarly to the first strategy, there is a bias at play here. We would like to have $A=H^{\top}\!DH$, but by doing $H^{\top}\!\mathtt{*}D\mathtt{*}H$ at line $4$ of algorithm~\ref{alg:second_test_strat} an approximation $\tilde{A}$ is computed instead.

Similarly to the first strategy, some confusion may arise by the fact that, by performing $H^{\top}\!\mathtt{*}D\mathtt{*}H$, an approximation $\tilde{A}$ of $A=H^{\top}\!DH$ is computed and fed to the algorithm.

\begin{oss}\label{oss:A_double_prec}
	The starting data $D$, $H$ is in double precision; $H$ is exactly representable in double precision because $H_{i,j}=\pm 1/\sqrt{n}$ and $n$ is a power of two. 	
	However, $A=H^{\top}DH$ may not belong to the set $\mathcal{F}^{n\times n}$ of matrices with double precision elements. Let $\mathtt{fl}(A)\in\mathcal{F}^{n\times n}$ be the closest matrix to $A$.
	
	The best that we can reasonably hope for is $\mathtt{fl}(A)$, but line 4 will in general compute something different (see Remark~\ref{oss:A_rel_err}). Note that by increasing the precision between lines $3$ and $4$ of algorithm~\ref{alg:second_test_strat} it is possible to obtain $\tilde{A}=\mathtt{fl}(A)$ (see also~\cite[p.64]{higham:accuracy_book}).
\end{oss}

\begin{oss}\label{oss:A_rel_err}
	How close will $\tilde{A}$ and $H^{\top}\!DH$ be, in general? $\tilde{A}$ will be formed in two steps as $K=H^{\top}\!\mathtt{*}D;\ \tilde{A}=K\mathtt{*}H$, and we know that multiplying by $H$ is a backward stable operation. For any unitarily invariant norm we have
	\begin{equation}\label{eqn:matmul_stability}
	\begin{aligned}
		K &= H^{\top}\!\mathtt{*}D=H^{\top}\!(D+\Delta D)&\text{with}\ \norm{\Delta D}\le O(u)\norm{D}\\
		\tilde{A} &= K\mathtt{*}H=(K+\Delta K)H&\text{with}\ \norm{\Delta K}\le O(u)\norm{K}
	\end{aligned}
	\end{equation}
	Now, $\tilde{A}=H^{\top}D\,H+H^{\top}\Delta{D}\,H+\Delta{K}\,H$, hence 
	\begin{align*}
		\norm*{\tilde{A}-H^{\top}\,D\,H} &= \norm*{H^{\top}\Delta{D}\,H + \Delta{K}\,H} = \norm*{H^{\top}\Delta{D} + \Delta{K}}\\
		 &\le\norm{\Delta D} + \norm{\Delta{K}}\le O(u)\qty(\norm{D}+\norm{K})\\
		 &\le O(u)\qty(\norm{D}+\norm{D+\Delta D})\le 3\,O(u)\norm{D}
	\end{align*}
	Note that numerous $O(u)$ factors have been incorporated into a single one, and the constant multiplying $u$ may hide a polynomial factor in $n$ of modest degree. %\textcolor{red}{direi 1. Forse 2. \`E importante?}
	In our case, the bound can be made even be more explicit. For example, $\norm{D}_2\le 50\sqrt{2}$.
\end{oss}
%\smallskip

Ideally, one would like to compare $A$ with $\exp(A)=H^{\top}\!\exp(D)H$. Reasoning as in Remark~\ref{oss:A_double_prec}, we must settle for $Y_{\textup{true}}$ being an approximation $\widetilde{\exp(A)}$ of $\exp(A)$.
The algorithm however is fed with $\tilde{A}$, not $A$, thus it returns and approximation $\hat{Y}$ of $\exponential(\tilde{A})$, not of $\exp(A)$. Therefore $\hat{Y}$ should be compared with a good proxy of $\exponential(\tilde{A})$, not with $Y_{\textup{true}}$.

\smallskip 

%\textcolor{red}{Nuovo da qui\dots}
Instead, in the second strategy $\hat{Y}$ is compared with $Y_{\textup{true}}$. Now,
\[
	\norm{\hat{Y}-Y_{\textup{true}}}\le\norm{\hat{Y}-\exponential(\tilde{A})}+\norm{\exponential(\tilde{A})-Y_{\textup{true}}}.
\]
As discussed, the first term $\norm*{\hat{Y}-\exponential(\tilde{A})}$ is the error that the algorithm actually achieves. The second term can be bounded as 
\begin{align*}
	\norm{\exponential(\tilde{A})-Y_{\textup{true}}}&=\norm{\exponential(\tilde{A})-H^{\top}\!\mathtt{*}\exp(D)\mathtt{*}H}\\
	&=\norm{\exp(H^{\top}DH+E_1)-H^{\top}\!\exp(D)H+E_2}\\
\intertext{with $\norm{E_1}\le O(u)\norm{D}$, $\norm{E_2}\le O(u)\norm{\exp(D)}$}
	&\le\norm{E_2}+\norm{\exp(H^{\top}DH+E_1)-\exp(H^{\top}DH)}.
\end{align*}
$E_1$ and $E_2$ are the forward errors in floating point matrix multiplication. 
Using equation~\eqref{eqn:backerr_fwerr_cond_relation},
\begin{align*}
	\norm{\exponential(\tilde{A})-Y_{\textup{true}}}&
		\begin{multlined}[t]
			\le O(u)\norm{\exp(D)}+\\
			\kappa_{\exp}(H^{\top}DH)\frac{\norm{E_1}}{\norm{H^{\top}DH}}\norm{\exp(A)}+o(\norm{E_1})
		\end{multlined}\\
	&=O(u)\norm{\exp(D)}+\kappa_{\exp}(A)O(u)\norm{\exp(A)}+O(u^2)\\
	&\overset{.}{\le}O(u)\norm{\exp(D)}(1+\kappa_{\exp}(A)),
\end{align*}
where $\overset{.}{\le}$ denotes inequality up to first order terms (i.e. higher order terms have been dropped).
\smallskip 

The bound for $\norm*{\exponential(\tilde{A})-Y_{\textup{true}}}$ depends on the conditioning of the exponential at $A$, or equivalently at $D$ (see~\cite[Cor.~3.12]{higham:matfun_book}). Instead, in the first testing strategy, the reference solution  $Y_{\textup{true}}$ can be made arbitrarily close to  $\exponential(\tilde{A}$), as the next section will describe.  

\begin{oss*}
	Note that the argument against the second testing strategy does not rely on the fact that matrix multiplications are performed, rather it relies on the fact that the output of the algorithm, $\hat{Y}$, is compared against an approximation of the exponential of a matrix that is (ever so slightly) different from the input to the algorithm. 
\end{oss*}

\subsection{Computing the reference solution}
\textcolor{red}{Aggiusta. Forse metti dopo?} The closed formula of the exponential of some test matrices $A$ is known, but the methods that will be shortly described struggle to compute $\exp(A)$. Thus, for a minority of the test matrices, $Y_{\textup{true}}$ was computed in advance, by evaluating the closed formula for the elements of $\exp(A)$ in high precision.
\smallskip 

\noindent Three strategies had initially been devised for the computation of the reference solution $Y_{\textup{true}}$. Ultimately, the chosen one was the third. It is interesting, however, to briefly describe them all.

In an earlier phase of testing, $Y_{\textup{true}}$ was being computed via diagonalization, i.e. as $Y_{\textup{true}}=\mathtt{V}*\exp(\mathtt{D})\,/\,\mathtt{V}$, where $\mathtt{V}$ and $\mathtt{D}$ are, respectively, the eigenvector and eigenvalue matrices returned by a high precision eigendecomposition. 
This strategy was not viable in many cases, though, because of the conditioning of the returned $\mathtt{V}$. 
In fact, many matrices are badly scaled or severely non-normal, thus yielding eigenvector matrices so ill-conditioned that a numerically accurate reconstruction of $A$ as $\mathtt{V}*\mathtt{D}\,/\,\mathtt{V}$ could not be obtained. Even worse, many test matrices are defective, thus they don't have a full set of linearly independent eigenvectors. Consequently, the condition number of the computed $\mathtt{V}$ grew, as the working precision was increased.

Therefore, diagonalization alone was not sufficient, a ``fallback method'' had to be present alongside it. 
The most immediate choice would have been a Taylor series expansion, but Scaling and Squaring would have been better. However, currently -- to the best of our knowledge -- there are no Julia libraries that implement Scaling and Squaring for the matrix exponential in arbitrary precision. Thus, the ``fallback method'' of choice was \texttt{exp\_mp}, the algorithm under test. Since preliminary tests and comparisons with diagonalization suggested that \texttt{exp\_mp} was accurate and reliable, this choice was not entirely unjustified.
\smallskip 

The second procedure to produce reference solutions avoided diagonalization altogether. Instead, \texttt{exp\_mp} was executed at progressively higher values of working precision, until the computed digits stabilized. More precisely, suppose that the goal was to compute $Y_{\textup{true}}$ with binary precision $\hat{p}$. Then $\norm{\exp(A)-Y_{\textup{true}}}/\norm{\exp(A)}$ should have roughly been of order $2^{-\hat{p}}$, i.e. $Y_{\textup{true}}$ and $\exp(A)$ should have matched up to approximately $\hat{p}\cdot\log_{10}(2)$ significant digits. \textcolor{red}{\`E utile questa specifica? Inutile? Dannosa, addirittura?}

A sequence of approximants $Y_p=\mathtt{exp\_mp}(A, \mathtt{working\_precision}=p)$ was computed at progressively higher values of $p$. This process was terminated when $\max_{i,j\in[n]}\abs{(Y_p-Y_{p-1})_{i,j}}$ falled below the tolerance value $2^{-\hat{p}}$, at which point $Y_p$ was kept as reference solution. 

The rationale behind this strategy is that \textcolor{red}{Spiegare.}

Again, the underlying assumption is that \texttt{exp\_mp} is able to approximate the exact matrix exponential up to (potentially) any level of precision. \textcolor{red}{Idea: le cifre che calcola, sono corrette}.

\textcolor{red}{Comunque, il fatto che si usi l'algoritmo che si sta testando non è proprio il massimo\dots Resta discutibile\dots}
\smallskip 

The third method to compute $Y_{\textup{true}}$ consisted in using \textsc{mpmath}~\cite{mpmath}. 
Being a Python library, this had to be done with Python calls from within Julia. There are many libraries that allow this, such as \texttt{PythonCall.jl}. Version $0.9.31$ was used in the proposed numerical experiments; the library is still actively maintained at the time of writing.

\textsc{mpmath} uses Scaling and Squaring with Taylor or diagonal Padé approximant to compute the matrix exponential. The chosen approximant was the former, which is the default one. The algorithm is described, in pseudocode, in code snippet~\ref{alg:mpmath_expm} \textcolor{red}{\`E indentato male perché al momento ho un po' di problemi con il pacchetto \texttt{algpseudocodex}, ma risolverò quanto prima.}
\begin{algorithm}[H]
	\caption{\emph{Pseudocode for \texttt{mpmath.expm}, Taylor version}}
	\label{alg:mpmath_expm}
	\begin{algorithmic}
		\Function{mpmath.expm}{$A$}
			\State $p\gets\mathtt{precision}(\ )$	\Comment{Gets the binary precision}
			\State $s\gets\max\qty{1,\lfloor\log_2(\norm{A}_{\infty})\rfloor}+\lfloor\frac{\sqrt{p}}{2}\rfloor$	\Comment{Scaling factor}
			\State $\mathtt{setprecision}(p+10+2s)$ \textbf{do}
				\State $\qquad A\gets 2^{-s}A$
				\State $\qquad T\gets A$
				\State $\qquad Y \gets I + T$
				\State $\qquad k\gets 2$
				\While{$\norm{T}_{\infty}<u_p$}
					\State $T\gets T\cdot\frac{A}{k}$
					\State $Y\gets Y+T$
					\State $k\gets k+1$
				\EndWhile
			\State \textbf{end} \Comment{setprecision}
			\State $Y\gets Y^{2^s}$
			\State \Return $Y$
		\EndFunction
	\end{algorithmic}
\end{algorithm}
