\chapter{Numerical Experiments}\label{capitolo:6}
In this chapter, the numerical experiments to assess and validate the \texttt{expm\_mp} algorithm will be thouroughly described. Then, their outcomes will be presented, emphasizing the most relevant ones. A critical discussion of the obtained results will be given, and conclusions will be drawn.

\section{Experimental setup}\label{sect:experimental_setup}
Since the algorithm under consideration operates in arbitrary precision, the main concern is accuracy.
In fact, multiprecision algorithms are frequently used to compute reference solutions against which lower precision methods are compared. Reliability is of paramount importance, more so than computational performance.

The testing strategies must therefore be designed carefully. More generally, the assessment of numerical algorithms is already a delicate task in itself; one that demands care and awareness, as each assumption and each approximation can have a huge impact on the overall process, an impact that can easily be overlooked.
As the working precision increases, these effects may become even more pronounced, in particular when a correspondingly higher level of accuracy is demanded. 

%The problem of designing the experimental setup can be a subtle one in general, the multiprecision setting in which the algorithm operates makes it even subtler than what it seems at first.
%Indeed, the finite-precision representation of the input and the output play an important role, more so as the precision is increased.

Well estabilished and widely accepted testing practices do exist; however there is no universally accepted and codified testing procedure, as each case has its own set of nuances.
\smallskip

In~\cite{higham:hf19_mpexpm} the proposed algorithm is tested on matrices taken from many sources, most of them having elements that are explicitly specified, such as
\begin{equation}\label{eqn:Higham_test_matrix}
	A = \begin{pmatrix}
		\mathtt{0} & \mathtt{1e{-4}}\\
		\mathtt{-1e{-4}} & \mathtt{0}
	\end{pmatrix}=
	\begin{pmatrix}
		\mathtt{0} & \mathtt{fl}(10^{-4}) \\
		\mathtt{fl}(-10^{-4}) & \mathtt{0}
	\end{pmatrix}.
\end{equation}
The reference solution is computed using  the \texttt{expm} function provided by the Multiprecision Computing Toolbox with $2d$ the significant digits, where $d$ is the number of digits of precision that the algorithm under test is running with. This first testing strategy can be described as in Algorithm~\ref{alg:first_test_strat}. 
\begin{algorithm}[H]
	\caption{\emph{First testing strategy}}
	\label{alg:first_test_strat}
	\begin{algorithmic}[1]
		\State $A = \mathtt{get\_from\_gallery}(\phantom{X})$ \Comment{\emph{$A$ is in double precision}}
		%\Lcomment{}
		\State $Y_{\textup{true}} = \mathtt{ref\_sol}(A)$	\Comment{\textit{Computes the reference solution}}
		\State $\hat{Y} = \mathtt{exp\_mp}(A)$
		\State \Return $\norm*{Y_{\textup{true}}-\hat{Y}}/\norm{Y_{\textup{true}}}$
	\end{algorithmic}
	%	\begin{algorithmic}
		%		\Function{ref\_sol}{$A$}
		%			\State 
		%		\EndFunction
		%	\end{algorithmic}
\end{algorithm}

For the accuracy analysis of the algorithm proposed in~\cite{exptayotf18}, the authors use matrices of the form $H^{\top}DH$, where $H$ is a Hadamard matrix normalized in order to be orthogonal (i.e. each entry is divided by $\sqrt{n}$), and $D$ is a diagonal matrix with entries uniformly randomly distributed in $[-50,50] + \mathtt{i}[-50,50]$. This second testing strategy can be described as in code snippet~\ref{alg:second_test_strat}.
\begin{algorithm}[H]
	\caption{\emph{Second testing strategy}}
	\label{alg:second_test_strat}
	\begin{algorithmic}[1]
		\State $H = \mathtt{hadamard}(n)$
		\State $H = H / \sqrt{n}$
		\State $D = \operatorname{Diag}\qty(100\,\mathtt{rand}(n)\mathtt{.-}50 + \mathtt{i}\qty(100\,\mathtt{rand}(n)\mathtt{.-}50))$
		\State $A = H^{\top}\!\mathtt{*}D\mathtt{*}H$ \Comment{\emph{$\mathcal{A}\coloneqq H^{\top}\!D H$}}
		\Statex
		\State $Y_{\textup{true}} = H^{\top}\!\mathtt{*}\exp(D)\mathtt{*}H$
		\State $\hat{Y} = \mathtt{exp\_mp}(A)$
		\State \Return $\norm*{Y_{\textup{true}}-\hat{Y}}/\norm{Y_{\textup{true}}}$
	\end{algorithmic}
\end{algorithm}

\noindent This second kind of test looks attractive at first, as the exact exponential of $\mathcal{A}$ can be cheaply and easily computed as $H^{\top}\!\exp(D)H$, theoretically, without the need to run multiprecision algorithms whose reliability is still being questioned. 
By contrast, one may raise two objections to the first testing strategy. Firstly, the reference is produced by an algorithm that is under scrutiny; secondly, and most importantly, the input data is in double precision and explicitly specified.

How can we then hope to observe an error less than $u_{53}$, even with an algorithm that uses higher precision internally? Since, as we've seen, promoting numerical expressions doesn't always improve the accuracy, is an error being introduced at the very start?
Is the accuracy of the computation -- whatever the precision it's being carried with -- limited by that of double precision floating point numbers? 
\smallskip

The latter strategy introduces a tiny error that the former one does not introduce. Furthermore, the three questions with which this section ends are misguiding and fallacious.  

\subsection{Discussing the first testing strategy}\label{subs:1st_strat_argument}
Let $\mathcal{F}^{n\times n}$ be the set of $n$-by-$n$ matrices with double precision elements, let $\mathtt{fl}(M)\in\mathcal{F}^{n\times n}$ be the closest matrix to a matrix $M$.
When one sees $A$ as in~\eqref{eqn:Higham_test_matrix} being passed to the multiprecision algorithm \texttt{exp\_mp}, one may think that there exists a matrix $\mathcal{A}\in\R{n}{n}$ s.t. $\mathtt{fl}(\mathcal{A})=A$ that was supposed to be passed instead of $A$, but can't be because of intrinsic errors. 
Following that line of reasoning, one may doubt the appropriateness of $A$ as a test matrix for \texttt{exp\_mp}, because the error in the input inherently prevents the method from computing $\mathcal{Y}\coloneqq\exp(\mathcal{A})$, the quantity that is actually desired.

Let $Y\coloneqq\exp(A)$; the algorithm \texttt{exp\_mp} will produce an approximation $\hat{Y}$ of $Y$. 
Notice that that $\hat{Y}$ may well approximate $Y$ while being a poor approximation of $\mathcal{Y}$, in fact
\begin{equation}\label{eqn:Y_rel_err_expansion}
	\begin{aligned}
		\frac{\norm*{\hat{Y}-\mathcal{Y}}}{\norm{\mathcal{Y}}} &= \frac{\norm*{\hat{Y}-Y+Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}\frac{\norm*{Y-\mathcal{Y}+\mathcal{Y}}}{\norm{\mathcal{Y}}}+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}\left(1+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\right)+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\\
		&\dot{=}\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}+\frac{\norm{Y-\mathcal{Y}}}{\norm{\mathcal{Y}}}\le\frac{\norm*{\hat{Y}-Y}}{\norm{Y}}+\kappa_{\exp}(\mathcal{A})\frac{\norm{\Delta\mathcal{A}}}{\norm{\mathcal{A}}}
	\end{aligned}
\end{equation}
where $\dot{=}$ denotes equality up to first order terms (i.e. higher order terms have been dropped). Note that in~\eqref{eqn:Y_rel_err_expansion} a term $\norm{\Delta\mathcal{A}}/\norm{\mathcal{A}}$ appears, with $\norm{\Delta\mathcal{A}}=O(u_{53})$, and is further amplified by $\kappa_{\exp}(\mathcal{A})$.

In practical applications, $\mathcal{Y}$ may represent ``the desired quantity''. Then Equation~\eqref{eqn:Y_rel_err_expansion} tells us that the algorithm may fail at computing the desired quantity.
While true, this doesn't constitute a valid reason to turn away the first testing strategy, because computing a ``desired quantity'' that can't possibly be computed using the data at our disposal was never our aim. It is outside the scope of any benchmark for our algorithm. The input to the algorithm is $A$, there is no reason why its output should approximate well the exponential of another matrix.

The matrix $A\in\mathcal{F}^{n\times n}$ is a real matrix like any other, as such is an appropriate input to a multiprecision algorithm. Our aim is to assess how well the algorithm approximates the matrix exponential \emph{of its input}. Note that $\exp(A)$ is unlikely to belong to $\mathcal{F}^{n\times n}$. 
Although $\exp(A)$ may never be computed exactly, a matrix arbitrarily close to it can be computed using multiprecision arithmetic, thus the error $\norm*{\hat{Y}-Y}/\norm{Y}$ can be arbitrarily small. This doesn't depend on whether $A$ is affected by intrinsic error or not, neither it depends on the precision of $A$. Errors of the order of $u_p$, with $p$ being the working precision of the algorithm, can be observed even if the input matrix $A$ is in double precision.

In conclusion, it is the forward relative error $\norm*{\hat{Y}-Y}/\norm{Y}$, and not $\norm*{\hat{Y}-\mathcal{Y}}/\norm{\mathcal{Y}}$, that correctly measures the quality of the approximations computed by the algorithm. If the former error is small, we can say that the algorithm is accurate.

\subsection{Discussing the second testing strategy}
Let's now consider the second testing strategy, which is summarized in the code snippet~\ref{alg:second_test_strat}.

Similarly to the first strategy, some confusion may arise by the fact that, by performing $H^{\top}\!\mathtt{*}D\mathtt{*}H$, an approximation $A$ of $\mathcal{A}=H^{\top}\!DH$ is computed and fed to the algorithm.

\begin{oss}\label{oss:A_double_prec}
	The starting data $D$, $H$ is in double precision; $H$ is exactly representable in double precision because $H_{i,j}=\pm 1/\sqrt{n}$ and $n$ is a power of two. 	
	However, $\mathcal{A}=H^{\top}DH$ may not belong to $\mathcal{F}^{n\times n}$.
	
	The best that we can reasonably hope for is $\mathtt{fl}(\mathcal{A})$, but line 4 of Algorithm~\ref{alg:second_test_strat} will in general compute something different (see Remark~\ref{oss:A_rel_err}). Note that by increasing the precision between lines $3$ and $4$ of Algorithm~\ref{alg:second_test_strat} it is possible to obtain $A=\mathtt{fl}(\mathcal{A})$ (see also~\cite[p.64]{higham:accuracy_book}).
\end{oss}

\begin{oss}\label{oss:A_rel_err}
	How close will $A$ and $H^{\top}\!DH$ be, in general? $A$ will be formed in two steps as $K=H^{\top}\!\mathtt{*}D;\ A=K\mathtt{*}H$, and we know that multiplying by $H$ is a backward stable operation. For any unitarily invariant norm we have
	\begin{equation}\label{eqn:matmul_stability}
	\begin{aligned}
		K &= H^{\top}\!\mathtt{*}D=H^{\top}\!(D+\Delta D)&\text{with}\ \norm{\Delta D}\le O(u)\norm{D}\\
		A &= K\mathtt{*}H=(K+\Delta K)H&\text{with}\ \norm{\Delta K}\le O(u)\norm{K}
	\end{aligned}
	\end{equation}
	Now, $A=H^{\top}D\,H+H^{\top}\Delta{D}\,H+\Delta{K}\,H$, hence 
	\begin{align*}
		\norm*{A-H^{\top}D\,H} &= \norm*{H^{\top}\Delta{D}\,H + \Delta{K}\,H} = \norm*{H^{\top}\Delta{D} + \Delta{K}}\\
		 &\le\norm{\Delta D} + \norm{\Delta{K}}\le O(u)\qty(\norm{D}+\norm{K})\\
		 &\le O(u)\qty(\norm{D}+\norm{D+\Delta D})\le 3\,O(u)\norm{D}
	\end{align*}
	Note that numerous $O(u)$ factors have been incorporated into a single one, and the constant multiplying $u$ may hide a polynomial factor in $n$ of modest degree. %\textcolor{red}{direi 1. Forse 2. \`E importante?}
	In our case, the bound can be made even be more explicit. For example, $\norm{D}_2\le 50\sqrt{2}$.
\end{oss}
%\smallskip

One may think, as in Section~\ref{subs:1st_strat_argument}, that the computed $\hat{Y}$ should be ideally compared with $\mathcal{Y}=\exp(\mathcal{A})=H^{\top}\!\exp(D)H$. Reasoning as in Remark~\ref{oss:A_double_prec}, $Y_{\textup{true}}$ is just an approximation $\widetilde{\exp(\mathcal{A})}$ of $\exp(\mathcal{A})$.
The algorithm however is fed with $A$, not $\mathcal{A}$, thus it returns and approximation $\hat{Y}$ of $\exp(A)$, not of $\exp(\mathcal{A})$. Therefore $\hat{Y}$ should be compared with a good proxy of $\exp(A)$, not with $Y_{\textup{true}}$.

Figure~\vref{fig:plot_expm_test2} pictures the situation. The ticks on the axis represent floating point data, they're widely spaced apart for illustration purposes. The curly brace between $\hat{Y}$ and $\exp(A)$ highlights the gap that is measured in the first testing strategy.
\begin{figure}[hbp]
	\centering
	\includegraphics[width=\textwidth]{Immagini/plot_expm_test2.pdf}
	\caption{\emph{Conceptual illustration of the absolute errors measured in the first and second testing strategies.}}
	\label{fig:plot_expm_test2}
\end{figure}
\smallskip 

Instead, in the second strategy $\hat{Y}$ is compared with $Y_{\textup{true}}$. In Figure~\ref{fig:plot_expm_test2}, the gap between the two terms is enclosed in a square brace. Now,
\[
	\norm{\hat{Y}-Y_{\textup{true}}}\le\norm{\hat{Y}-\exp(A)}+\norm{\exp(A)-Y_{\textup{true}}}.
\]
As discussed, the first term $\norm*{\hat{Y}-\exp(A)}$ is the error that the algorithm actually achieves. Figure~\ref{fig:plot_expm_test2} suggests that this second term should be roughly of size $\norm{L_{\exp}(\mathcal{A})}\norm*{\mathcal{A}-A}$. Let us give a more rigorous bound. 
\begin{align*}
	\norm{\exp(A)-Y_{\textup{true}}}&=\norm{\exp(A)-H^{\top}\!\mathtt{*}\exp(D)\mathtt{*}H}\\
	&=\norm{\exp(H^{\top}\!DH+E_1)-H^{\top}\!\exp(D)H+E_2}\\
\intertext{with $\norm{E_1}\le O(u)\norm{D}$, $\norm{E_2}\le O(u)\norm{\exp(D)}$}
	&\le\norm{E_2}+\norm{\exp(H^{\top}\!DH+E_1)-\exp(H^{\top}\!DH)}.
\end{align*}
$E_1$ and $E_2$ are the forward errors in floating point matrix multiplication. 
Using equation~\eqref{eqn:backerr_fwerr_cond_relation},
\begin{align*}
	\norm{\exp(A)-Y_{\textup{true}}}&
		\begin{multlined}[t]
			\le O(u)\norm{\exp(D)}+\\
			\kappa_{\exp}(H^{\top}DH)\frac{\norm{E_1}}{\norm{H^{\top}DH}}\norm{\exp(\mathcal{A})}+o(\norm{E_1})
		\end{multlined}\\
	&=O(u)\norm{\exp(D)}+\kappa_{\exp}(\mathcal{A})O(u)\norm{\exp(\mathcal{A})}+O(u^2)\\
	&\overset{.}{\le}O(u)\norm{\exp(D)}(1+\kappa_{\exp}(\mathcal{A})),
\end{align*}
where $\overset{.}{\le}$ denotes inequality up to first order terms (i.e. higher order terms have been dropped).
\smallskip 

The bound for $\norm*{\exp(A)-Y_{\textup{true}}}$ depends on the conditioning of the exponential at $\mathcal{A}$, or equivalently at $D$ (see~\cite[Cor.~3.12]{higham:matfun_book}). Instead, in the first testing strategy, the reference solution  $Y_{\textup{true}}$ can be made arbitrarily close to  $\exp(A)$, as the next section will describe.  

\begin{oss*}
	Note that the argument against the second testing strategy does not rely on the fact that matrix multiplications are performed, rather it relies on the fact that the output of the algorithm, $\hat{Y}$, is compared against an approximation of the exponential of a matrix that is (ever so slightly) different from the input to the algorithm. 
\end{oss*}

\begin{oss*}
	In~\cite{exptayotf18}, the authors also propose numerical experiments analogous to those described in Algorithm~\ref{alg:second_test_strat}, but in which $\mathcal{A}$ is of the form $H^{\top}\!JH$ with $J$ being a Jordan form that makes $\mathcal{A}$ defective.
	
	The error bounds and the discussions in this section hold in this case as well. In fact, the crucial aspects are the unitary change of basis $H$ and the matrix multiplications performed in floating-point arithmetic. 
\end{oss*}

\subsection{Computing the reference solution}\label{subs:computing_refsol}
The exponential of some of the test matrices is known in closed formula. For $8$ test matrices ($152$ samples), $Y_{\textup{true}}$ was computed in advance, by evaluating the formula at a high precision $\hat{p}$. This was done only for the matrices $A$ for which it would be guaranteed that $Y_{\textup{true}}=\exp(A)+E$ such that $\norm{E}/\norm{\exp(A)}=O(u_{\hat{p}})$, and for which there was the ``suspicion'' that the methods to compute the reference solution wouldn't return a good approximation of $\exp(A)$, or at least not as good as the high precision evaluation of its closed formula.
\begin{esempio}
	Let $b=10^4$ and let
	\vspace{-1em}
	\[
		A = \begin{pmatrix}
			1-\frac{b}{2} & \frac{b}{2}\\
			-\frac{b}{2} & 1+\frac{b}{2}
		\end{pmatrix}=
		\begin{pmatrix}
			1 & 0 \\ 0 & 1
		\end{pmatrix}+\!\quad\raisebox{6.5pt}{$
		\begin{NiceArray}{ccc}[first-row]
			 \Hbrace{1}{\coloneqq u} & \Hbrace{2}{\coloneqq v^{\top}}\\
			 1 & -\frac{b}{2} & \frac{b}{2}\\
			 1 & & \\
		\CodeAfter
			\SubMatrix({1-1}{2-1})
			\SubMatrix({1-2}{1-3})
			%\OverBrace[shorten, yshift=3pt]{1-1}{2-1}{\mathsmaller{\coloneqq u}}
			%\OverBrace[shorten, yshift=3pt]{1-2}{1-3}{\tiny\coloneqq v^\top}
		\end{NiceArray}$}\,\ =I+uv^{\top}
	\]
	A is a rank 1 correction of the identity. There is an explicit formula for the function of such matrices, see~\cite[Eqn.~1.16]{higham:matfun_book}. By applying it, we get
	\begin{align*}
		\exp(A) &= \exp(I+uv^{\top}) = \exp(1)I + \exp\!\qty[1+\langle u,v\rangle,1]\,uv^{\top}\\
		&=\exp(1)I+\exp[1,1]\,uv^{\top} = \exp(1)I+\exp'(1)\,uv^{\top}\\
		&=\exp(1)\qty(I+uv^{\top}) = \exp(1) A,
	\end{align*}
	which can be easily evaluated in arbitrary precision.
\end{esempio}
For the vast majority of the test matrices, the reference solution was computed using another numerical method, which we will now describe.
\smallskip 

In an earlier phase of testing, $Y_{\textup{true}}$ was being computed via diagonalization, i.e. as described in Section~\vref{subs:diagonalization}. 
This strategy was not viable in many cases, though, because of the conditioning of the returned eigenvector matrix $\mathtt{V}$. 
In fact, many matrices are badly scaled or severely non-normal, thus their computed eigenvector matrices were so ill-conditioned that a numerically accurate reconstruction of $A$ as $\mathtt{V}*\mathtt{D}\,/\,\mathtt{V}$ -- with $\mathtt{D}$ being the computed eigenvalue matrix --  could not be obtained. Even worse, many test matrices are defective, thus they don't have a full set of linearly independent eigenvectors. Consequently, the condition number of the computed $\mathtt{V}$ grew, as the working precision was increased (see also the discussion in Section~\ref{subs:diagonalization}).

Therefore, diagonalization alone was not sufficient, a ``fallback method'' had to be present alongside it. 
The most immediate choice would have been a Taylor series expansion, but scaling and squaring would have been better. However, currently -- to the best of our knowledge -- there are no Julia libraries that implement scaling and squaring for the matrix exponential in arbitrary precision. Thus, the ``fallback method'' of choice was \texttt{exp\_mp}, the algorithm under test, in higher precision. Since preliminary tests and comparisons with diagonalization suggested that \texttt{exp\_mp} was accurate and reliable, this choice was not entirely unjustified.

Ultimately, $Y_{\textup{true}}$ was computed using \textsc{mpmath}~\cite{mpmath}. 
Being a Python library, this had to be done with Python calls from within Julia. There are many libraries that allow this, such as \texttt{PythonCall.jl}. Version $0.9.31$ was used in the proposed numerical experiments; the library is still actively maintained at the time of writing.

\textsc{mpmath} uses scaling and squaring with Taylor or diagonal Padé approximant to compute the matrix exponential. The chosen approximant was the former, which is the default one. The algorithm is described, in pseudocode, in Algorithm~\ref{alg:mpmath_expm}.
\begin{algorithm}[H]
	\caption{\emph{Pseudocode for \texttt{mpmath.expm}, Taylor version}}
	\label{alg:mpmath_expm}
	\begin{algorithmic}
		\Function{mpmath.expm}{$A$}
			\State $p\gets\mathtt{precision}(\ )$	\Comment{\textit{Gets the binary precision}}
			\State $s\gets\max\qty{1,\lfloor\log_2(\norm{A}_{\infty})\rfloor}+\lfloor\frac{\sqrt{p}}{2}\rfloor$	\Comment{\textit{Scaling factor}}
			\With{$\mathtt{setprecision}(p+10+2s)$}
				\State $A\gets 2^{-s}A$
				\State $T\gets A$
				\State $Y \gets I + T$
				\State $k\gets 2$
				\While{$\norm{T}_{\infty}<u_p$}
					\State $T\gets T\cdot\frac{A}{k}$
					\State $Y\gets Y+T$
					\State $k\gets k+1$
				\EndWhile
			\EndWith
			\State $Y\gets Y^{2^s}$\Comment{Squaring phase}
%			\For{$\_=1,\dots,s$} 
%				\State $Y\gets Y\mathtt{*}Y$
%			\EndFor	
			\State \Return $Y$
		\EndFunction
	\end{algorithmic}
\end{algorithm}
Like \texttt{exp\_mp}, \texttt{mpmath.expm} internally increases the working precision.
Notice how, unlike \texttt{exp\_mp}, \texttt{mpmath.expm} doesn't compute the exponential of Hermitian matrices via diagonalization.

We briefly recall how to interpret a performance profile plot, adapting the explaination to the present setting. For the sake of explaination, a performance profile plot is composed of multiple curves called \emph{performance profiles}, each relative to one configuration of \texttt{exp\_mp}. A point $(\tau,c)$ on the performance profile specifies the fraction $c$ of samples for which the \texttt{exp\_mp} variant achieved a relative error within a factor $\tau$ from the relative error obtained by the algorithm that best approximates the exponential of the sample's matrix.

So, at $\tau=1$ the performance profile gives the fraction of samples for which the corresponding variant was the most accurate. The sum of all the performance profile values at $\tau=1$ can exceed $1$, as ties are possible.
For each variant, the bigger the $\tau$ is, the more samples are such that the relative error is within a factor $\tau$ from the best result; therefore the performance profiles are nondecreasing functions of $\tau$. Their growth behaviour, as $\tau$ increases, reveals the reliability of the corresponding configuration.
Indeed, by reading it farther and farther right, the performance profile plot tells how many matrix exponentials are \emph{eventually} computed by the corresponding configuration. 
A performance profile curve remaining flat may indicate that the configuration performs very well on some samples, but very poorly on others (or even fail to compute their underlying matrix exponential altogether). 

A preliminary analysis of the performance profiles revealed that, for almost all samples, the ratio between the forward error of the sample and the smallest error attained in the computation of the same matrix exponential was below $\tau=100$; therefore the maximum value on the horizontal axis was set to $100$. Note that if, for some test matrices, a configuration achieved a positive relative error but another configuration managed to compute the corresponding $Y_{\textup{true}}$ exactly, then its performance profile would never reach the value $1$ except in the limit. As noted in Remark~\ref{oss:failed_computations}, some configurations fail to compute the exponential of some matrices, thus their performance profile doesn't converge to $1$. \newline
All in all, the closer the performance profile is to the top left corner, the better.
\smallskip

When the working precision is $851$, \texttt{exp\_d} outperforms the other variants. However, all of them achieve relative errors within a factor $100$ from the lowest, on almost all prolems.

\section{Is \texorpdfstring{$\delta$}{δ} an upper bound to the truncation error?}\label{sect:is_delta_bound?}
Recall that in \texttt{exp\_mp} the final value of $\delta$, according to its definition, bounds the absolute truncation error $\norm{\exp(2^{-s}X)-r_m(2^{-s}X)}_1$, where $m$ and $s$ here are the approximant degree and scaling factors obtained at the end of the modified scaling phase, and $X$ is the transformed version of $A$ (see the discussion in Section~\ref{sect:exp_mp_description}).
We already noted that $\delta$ should not be compared with the truncation error of the computed approximation of $\exp(A)$, see Remark~\ref{oss:delta_not_upper_bound}.

However, it's interesting to check whether the aforementioned property of $\delta$ is satisfied in practice.
To test this, the experiments described in Section~\ref{sect:experimental_setup} have been executed by returning the unscaled matrix exponential, correctly transformed. The reference solution has been computed using \textsc{mpmath}. The Hermitian test matrices have been excluded by the analysis, since the computation of their exponential by \texttt{exp\_mp} doesn't involve $\delta$. The samples corresponding to Julia's \texttt{expm} have been excluded for the same reason.   

Figure~\ref{fig:delta_abserr_direct_comparison} provides the answer, at a glance. In the left plots of the figure, the overwhelming majority of the datapoits relative to $\delta$ are below the ones corresponding to the absolute error $\norm{\exp(2^{-s}A)-r_m(2^{-s}A)}_1$. We should observe the opposite behaviour.

The plots in the right column of the figure compare the ratio $\delta/\psi$ with 
\[
	\frac{\norm{\exp(2^{-s}A)-r_m(2^{-s}A)}_1}{\norm{\exp(2^{-s}A)}_1},
\]
i.e. the relative error in the 1-norm. Since -- as noted in Remark~\ref{oss:psi_not_lower_bound} -- $\psi$ is not a lower bound to $\norm{\exp(2^{-s}A)}_1$, there is no theoretical guarantee that $\delta/\psi$ bounds the relative error. Although this comparison is less significant than the one in the plots in the left-hand side, it is equally interesting.

\begin{figure}[htp]
	\centering
	\includegraphics[width=\textwidth]{Immagini/delta_abs_err_1_direct_comparison}
	\caption{\emph{Comparison between the values of $\delta$ and the absolute error in the 1-norm (left plots), comparison between $\delta/\psi$ and the relative error in the 1-norm (right plots), grouped by working precision value.}}
	\label{fig:delta_abserr_direct_comparison}
\end{figure}

It turns out that $\norm{\exp(2^{-s}A)-r_m(2^{-s}A)}_1\le\delta$ in only $71$ of the $1832$ samples considered for this analysis. The computed value of $\delta$ is exactly zero in $188$ of the samples, but only $45$ of these also have a zero absolute error. 

Figure~\ref{fig:delta_abserr_ratio} displays the ratios between the value of $\delta$ and the forward error it is supposed to bound, for each sample. The figure suggests that both approximants yield equally poor results, as the values of $\delta$ returned by the algorithm are significantly smaller than the error it is supposed to bound.

\begin{figure}[hbp]
	\centering
	\includegraphics[width=0.75\textwidth]{Immagini/delta_abs_err_1_ratio}
	\caption{\emph{Ratio between $\delta$ and the absolute truncation error in the 1-norm, grouped by working precision value, hued by approximant.}}
	\label{fig:delta_abserr_ratio}
\end{figure}

A closer look at Figure~\ref{fig:delta_abserr_direct_comparison} reveals that the plotted errors are of the order of machine precision. Indeed, the observed behaviour is explained by the fact that $\exp(2^{-s}A)$ is not actually compared with $r_m(2^{-s}A)$, but with a floating point approximation.

Considering absolute errors for simplicity, the datapoints actually represent the quantity
$\norm{Y-\tilde{r}_m(2^{-s}A)}_1$ where $Y$ is the high-precision approximation of $\exp(2^{-s}A)$ computed by \textsc{mpmath} and $\tilde{r}_m(2^{-s}A)$ is the floating point approximation of $r_m(2^{-s}A)$ computed by \texttt{exp\_mp}. In fact, the algorithm performs all arithmetic operations at a finite working precision, thus it can only approximate $r_m(2^{-s}A)$ at the corresponding level of accuracy.
Since
\begin{equation}\label{eqn:absolute_error_delta_ub}
	\norm{Y-\tilde{r}_m(2^{-s}A)}_1\le\norm{Y-r_m(2^{-s}A)}_1+\norm{r_m(2^{-s}A)-\tilde{r}_m(2^{-s}A)}_1
\end{equation}
and the second term in the left-hand side of~\eqref{eqn:absolute_error_delta_ub} is such that 
\[
	\norm{r_m(2^{-s}A)-\tilde{r}_m(2^{-s}A)}_1\le O(u_p)\norm{r_m(2^{-s}A)}
\]
where $p$ is the working precision of \texttt{exp\_mp}, it is not surprising that the error values in the left-hand side plots of Figure~\ref{fig:delta_abserr_direct_comparison} are of the order of machine precision.

\begin{oss*}
	The first summand $\norm{Y-r_m(A)}_1$ in the left-hand side of~\ref{eqn:absolute_error_delta_ub} is not the quantity bounded by $\delta$. However, $Y$ can be made arbitrarily close to $\exp(A)$.
	
	A close approximation to $r_m(2^{-s}A)$ could be obtained by computing the powers of $A$ at a high precision, evaluating $U_{\textup{e}}$ and $U_{\textup{o}}$ and finally by solving $(U_{\textup{e}}-U_{\textup{o}})\backslash\,(U_{\textup{e}}+U_{\textup{o}})$ at a high precision. Note that the working precision should be chosen so that the rounding errors in this computation are negligible with respect to the value of $\delta$ returned by \texttt{exp\_mp} \textcolor{red}{giusto?}. 
	Moreover, the described procedure would assess the validity of the truncation error bound itself, but this is not a property of the \texttt{exp\_mp} algorithm. Hence, it would provide little insight into the the rounding errors that it introduced. \textcolor{red}{Ci sta, come considerazione?}
	
	%Moreover, while the described procedure would assess the validity of the truncation error bound itself, it would tell us little about the errors committed by the algorithm that evaluates the approximant, as the two are unrelated
\end{oss*}

Analogous considerations can be made for the relative errors displayed in the plots in the left-hand side of Figure~\ref{fig:delta_abserr_direct_comparison}, since it holds that 
\[
	\frac{\norm{Y-\tilde{r}_m(2^{-s}A)}_1}{\norm{Y}_1}\overset{.}{\le}\frac{\norm{Y-r_m(2^{-s}A)}_1}{\norm{Y}_1}+\frac{\norm{r_m(2^{-s}A)-\tilde{r}_m(2^{-s}A)}_1}{\norm{r_m(2^{-s}A)}_1}.
\]
